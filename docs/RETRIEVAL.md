# Слой поиска и ранжирования

Документ описывает контур Data / IR: как LitGraphAgent выбирает источники,
собирает кандидатов, чистит дубликаты и отбирает статьи в квоту.
Общая схема системы — [ARCHITECTURE.md](ARCHITECTURE.md).

## 1. Каталог движков

`lit_graph/search/tools.py` описывает доступные движки как данные, а не как
жёстко зашитые ветки кода. Для каждого движка указаны:

- ключ (`semantic_scholar`, `arxiv`, `web`);
- человекочитаемое название и краткое описание;
- сильные и слабые стороны;
- типовые сценарии, где движок уместен.

Каталог доступен из CLI:

```bash
litgraph --tools
```

Модель видит этот каталог в промпте и возвращает `primary` / `fallback`
наборы. Это позволяет менять приоритеты без переписывания retrieval-кода.

## 2. Маршрутизация

`SearchRouter` (`lit_graph/search/router.py`) — валидатор решения модели:

1. нормализует ключи движков;
2. отбрасывает неизвестные значения;
3. ограничивает число primary-движков (`SEARCH_ROUTER_MAX_PRIMARY`);
4. подбирает fallback, если модель его не предложила;
5. сохраняет обоснование и источник решения.

Если модель недоступна или ответ невалиден, роутер строит эвристический план.
Флаги `--engines` и `--no-router` полностью обходят LLM-выбор.

Итоговый план хранится в `_state.json` как `search_plan` и печатается при
запуске: какие движки выбраны, почему и кто принял решение.

## 3. Сбор кандидатов

`RetrievalAgent.search` выполняет план:

1. запрашивает primary-движки;
2. добавляет fallback, если результатов меньше
   `SEARCH_FALLBACK_MIN_RESULTS`;
3. генерирует уточняющие подзапросы, пока не набрана квота;
4. объединяет метаданные и убирает дубликаты по DOI, URL и нормализованному
   названию;
5. сохраняет `source_engine` для каждого кандидата.

Клиенты (`arxiv_client.py`, `s2_client.py`, `web_scraper.py`) используют общий
HTTP-слой с таймаутами, повторами и дисковым кэшем.

## 4. Ранжирование и elbow cutoff

`lit_graph/search/ranking.py` считает наукометрический скор:

- citation velocity — цитирования с поправкой на возраст статьи;
- influential citation ratio — доля влиятельных цитирований;
- log-scaled impact — сглаженный общий импакт.

Скоры нормализуются в непрерывный вес. Затем `ENABLE_ELBOW_CUTOFF` отсекает
низкоимпактный хвост по изгибу кривой, а `MIN_PAPERS_PER_RUN` и
`MAX_PAPERS_PER_RUN` задают допустимые границы квоты.

## 5. Citation expansion и PDF

`expand_citations` добавляет referenced/citing работы, чтобы граф не терял
связи между источниками. В режиме `--deep` `fetch_pages` скачивает
open-access PDF, извлекает текст постранично и передаёт его в промпт
grounding-а, чтобы определения концептов ссылались на конкретные страницы.

## 6. Инварианты

- Новый движок добавляется в каталог и в фабрику клиентов, а не в условие
  внутри агента.
- Решение модели всегда валидируется; невалидный план не попадает в состояние.
- Каждый кандидат несёт `source_engine`.
- Сетевые ошибки не роняют весь прогон: кандидат пропускается, причина
  попадает в лог.
- Кэш можно отключить флагом `--no-cache`.

## 7. Проверка

```bash
pytest tests/test_search.py tests/test_search_router.py tests/test_ranking.py -q
litgraph --tools
```

Тесты покрывают выбор движков, fallback, дедупликацию, ранжирование и
устойчивость к невалидному ответу модели.
