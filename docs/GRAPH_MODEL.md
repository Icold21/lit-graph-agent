# Модель графа и Obsidian vault

Документ описывает онтологию, каноникализацию концептов и правила записи
vault. Общая архитектура — [ARCHITECTURE.md](ARCHITECTURE.md).

## 1. Онтология

Vault состоит из четырёх типов заметок:

| Тип | Каталог | Назначение |
| --- | --- | --- |
| Источник | `Sources/` | Атомарная заметка о статье: метаданные, выжимка, цитата |
| Концепт | `Concepts/` | Hub концепта: определение, упоминания, обратные ссылки |
| Внешняя ссылка | `Sources/` | Stub для работы, которой нет в базе, чтобы `[[wikilink]]` не повисал |
| Синтез | корень | Обзор, библиография, журнал активности |

Рёбра графа:

- `paper → concept` — статья упоминает концепт;
- `paper → paper` — цитирование, тип `cites`;
- `concept → paper` — обратная ссылка, генерируется вместе с hub.

## 2. Каноникализация

LLM возвращает нестабильные имена: `Transformer` / `Transformers`,
`GNN` / `Graph Neural Networks (GNNs)`. `lit_graph/agent/concepts.py` сводит их
к одному ключу:

1. нормализация пробелов и обрезка пунктуации;
2. снятие parenthetical-части, если она является сокращением;
3. раскрытие известных акронимов (`GNN` → `graph neural network`);
4. singularization последнего слова с учётом uncountable-слов;
5. выбор самого частого display-варианта, тай-брейк — алфавитный.

`concept_key` используется для сравнения, `display_name` — для заголовка
заметки и `[[wikilinks]]`.

## 3. Порог и бюджет концептов

- `MIN_CONCEPT_PAPERS` отсекает концепты, встретившиеся меньше чем в N статьях;
- `MAX_CONCEPTS_PER_PAPER` ограничивает число концептов на статью;
- `CONCEPT_BATCH_SIZE` задаёт размер батча при генерации определений.

Порог применяется к каноническим ключам, поэтому разные написания одного
концепта не считаются разными сущностями.

## 4. Запись vault

Все записи идут через `GraphAgent`:

- `rebuild_graph` собирает концепты, веса и рёбра из состояния;
- `flush` создаёт/обновляет заметки, библиографию, обзор и журнал;
- существующие определения концептов не перезаписываются при `--update`;
- имена файлов стабильны и безопасны для Windows/macOS/Linux;
- YAML экранируется, чтобы двоеточия и кавычки не ломали frontmatter.

## 5. Ссылочная целостность

- Каждый концепт получает hub с обратными ссылками на источники.
- Внешние работы получают stub-заметку, поэтому unresolved links не
  появляются.
- `graph.json` сливается с пользовательскими настройками Obsidian, а не
  перезаписывает их.
- QA-агент отдельно проверяет unresolved links, orphans и дубли рёбер.

## 6. Веса и визуализация

Вес концепта зависит от числа упоминаний и наукометрического веса статей.
Непрерывная нормализация позволяет использовать размер узла в graph view без
резких скачков. Пресет графа устанавливается при первом запуске и дальше
только дополняется.

## 7. Проверка

```bash
pytest tests/test_concepts.py tests/test_obsidian.py tests/test_vault_names.py -q
litgraph --check --id <base>
```

Тесты покрывают плюралы, регистр, акронимы, parenthetical merging, безопасные
имена файлов и слияние graph preset.
